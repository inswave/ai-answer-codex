`gridView`의 기본 셀 병합은 `mergeCells` 속성 또는 `mergeCells()` API로 적용할 수 있습니다. 연속된 동일 데이터 기준으로 병합하며, 대표적으로 컬럼 방향 병합은 `bycol`, 행 방향 병합은 `byrow`를 사용합니다.

적용 방법은 다음과 같습니다.

1. 그리드 전체 병합 방식은 `gridView`의 `mergeCells`에 지정합니다.
2. 특정 컬럼만 병합하려면 `mergeCol`에 컬럼 ID를 콤마로 지정합니다.
3. 화면 로딩 후 동적으로 적용해야 하면 `gridViewId.mergeCells("bycol")` 형태로 호출합니다.

예시입니다.

```xml
<w2:gridView id="grd_gridView1"
    dataList="dlt_data"
    mergeCells="bycol"
    mergeCol="col1,col3">
</w2:gridView>
```

```javascript
// grd_gridView1은 예시 gridView ID입니다.
grd_gridView1.mergeCells("bycol");
```

주요 옵션은 다음과 같습니다.

- `bycol`: 같은 컬럼에서 연속적으로 같은 데이터가 있는 행을 병합
- `byrow`: 같은 행에서 연속적으로 같은 데이터가 있는 컬럼을 병합
- `bycolrec`: `bycol` 처리 후 병합되지 않은 셀을 대상으로 `byrow` 처리
- `byrowrec`: `byrow` 처리 후 병합되지 않은 셀을 대상으로 `bycol` 처리
- `byrestriccol`: 왼쪽 컬럼의 병합 상태를 기준으로 우측 컬럼을 제한 병합
- `never`: 병합 해제

`colMerge`는 실제 셀 병합이 아니라 동일 데이터의 border를 제거해 병합처럼 보이게 하는 방식이므로, 병합된 셀 기준의 정렬이나 병합 제어가 필요하면 `mergeCells` 방식을 사용해 주세요. 병합이 적용되지 않거나 의도와 다르게 보이는 경우에는 사용 중인 엔진 버전, `gridView` XML, `dataList` 샘플 데이터, 적용하려는 병합 기준 컬럼을 함께 전달해 주시면 추가 확인이 가능합니다.

`submission` 요청 timeout은 `Submission`의 `timeout` 속성으로 설정할 수 있습니다.  
공통 기본값을 변경하려면 WebSquare 설정파일의 `/WebSquare/submission/timeout/@value` 값을 확인하고, 개별 요청별로 다르게 적용하려면 해당 `submission` 객체에 `timeout`을 지정합니다.

적용 방법은 다음과 같습니다.

1. 전체 `submission` 기본 timeout은 설정파일에서 `/WebSquare/submission/timeout/@value`를 설정합니다.
2. 특정 `submission`만 조정하려면 해당 `submission`에 `timeout` 속성을 지정합니다.
3. `timeout` 값은 ms 단위로 설정합니다.
4. 설정한 시간이 초과되어도 응답이 없으면 error callback 또는 submission error 처리로 진입합니다.

예시는 다음과 같습니다.

```xml
<xf:submission id="sbm_search"
    action="/sample/search.do"
    method="post"
    mode="asynchronous"
    timeout="60000"
    processMsg="조회 중입니다." />
```

위 예시는 `sbm_search` 요청에 대해 60초 timeout을 설정하는 예입니다.  
참고 사례 기준으로 `timeout`을 별도로 설정하지 않은 경우 기본값은 `0`, 즉 무한 대기로 동작할 수 있으나, 실제 대기 지속 여부는 브라우저, 네트워크, WAS, 프록시, 방화벽 timeout 설정의 영향을 받을 수 있습니다.

`submission error(E03). Status[12002]`가 함께 발생한다면 클라이언트 요청 timeout 또는 네트워크/서버 응답 지연 가능성을 우선 확인해 주십시오.  
정확한 판단을 위해 사용 중인 WebSquare 엔진 버전, 설정파일의 `/WebSquare/submission/timeout/@value`, 해당 `submission` XML, 발생 시 브라우저 개발자도구 Network 결과를 함께 확인하는 것이 좋습니다.

selectBox 항목은 바인딩된 `dataList`의 데이터를 변경하거나, `linkedDataList`의 Filter Condition을 이용해 동적으로 구성할 수 있습니다. 그리드 셀의 `inputType: "select"` 컬럼은 행별로 서로 다른 `dataList`를 직접 바인딩하는 API는 제공되지 않으며, 컬럼 단위 동적 바인딩은 `setColumnNodeSet( colIndex, nodeset, label, value )` 방식으로 처리하는 유사 사례가 있습니다.

적용 방법은 다음과 같습니다.

1. 일반 `selectBox`는 항목용 `dataList`를 먼저 바인딩합니다.
2. 조회나 선택값 변경 시점에 해당 `dataList`의 데이터를 변경합니다.
3. 다른 selectBox 값에 따라 항목을 필터링해야 하면 `linkedDataList`의 Filter Condition을 사용합니다.
4. 그리드 컬럼 select 항목을 바꿔야 하면 행별이 아니라 컬럼 기준으로 `setColumnNodeSet()` 적용을 검토합니다.

예를 들어 `linkedDataList` Filter Condition은 유사 사례 기준으로 다음과 같이 설정할 수 있습니다.

```javascript
// 예: type 컬럼 값이 selectBox1의 value와 같은 항목만 표시
type == val('selectBox1')
```

그리드 select 컬럼에 동적으로 항목을 다시 연결하는 경우는 다음 형태를 참고해 주세요.

```javascript
// colIndex, nodeset, label, value는 화면 구조에 맞게 지정
gridView1.setColumnNodeSet(colIndex, nodeset, "name", "code");
```

`dataList` 자체의 값을 스크립트로 변경해야 하는 경우에는 `dataList` API를 사용해 데이터를 갱신한 뒤, 해당 `dataList`를 참조하는 selectBox가 변경된 데이터를 사용하도록 구성합니다.

```javascript
// 예: 사용자 정의 예시입니다.
dataList1.setCellData(0, "name", "사과");
```

주의사항으로, 그리드의 각 row마다 서로 다른 항목 목록을 직접 바인딩해야 하는 요구라면 WebSquare 그리드 select 컬럼 구조만으로는 제한이 있을 수 있습니다. 이 경우 row별로 독립된 selectBox가 필요한 화면 구조인지, 또는 테이블/반복 영역 형태로 구성하는 방식이 적합한지 검토해 주세요. 정확한 예시는 사용 중인 엔진 버전, 일반 `selectBox`인지 `gridView` 셀 select인지, 현재 바인딩 XML 또는 화면 구조를 함께 확인하면 더 구체적으로 안내드릴 수 있습니다.

`$p.dynamicCreate`를 사용하면 런타임에 WebSquare 컴포넌트를 동적으로 생성할 수 있습니다. 기본 형식은 `$p.dynamicCreate(id, componentName, options, parent)`이며, 생성할 컴포넌트 ID, 컴포넌트명, 생성 옵션, 추가할 부모 컴포넌트를 지정합니다.

2. `$p.dynamicCreate`의 `id`는 화면 내에서 중복되지 않도록 지정합니다.
3. `componentName`에는 생성할 WebSquare 컴포넌트명을 지정합니다. 예: `group`, `input`, `trigger`, `selectbox`
4. `options`에는 `style`, `className`, `placeholder` 등 생성 시 적용할 속성을 Object 형식으로 전달합니다.
