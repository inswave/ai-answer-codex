`gridView`의 셀 병합은 `mergeCells` 속성 또는 `mergeCells()` API로 적용할 수 있습니다. 연속된 동일 데이터 기준으로 병합하며, 세로 방향은 `bycol`, 가로 방향은 `byrow`를 사용합니다.

적용 방법은 다음과 같습니다.

1. GridView에 `mergeCells` 속성으로 병합 방식을 지정합니다.
2. 특정 컬럼만 병합 대상에 포함하려면 `mergeCol` 속성에 컬럼 ID를 콤마로 구분해 지정합니다.
3. 조회, 필터 변경 등으로 데이터가 변경된 뒤 다시 병합해야 하는 경우 `gridView.mergeCells("bycol")` 형식으로 병합 API를 다시 호출합니다.

예시입니다. `grd_gridView1`, `dataList1`, `col1`, `col3`은 사용자 정의 예시이며 공식 API명이 아닙니다.

```xml
<w2:gridView id="grd_gridView1"
    dataList="dataList1"
    mergeCells="bycol"
    mergeCol="col1,col3">
</w2:gridView>
```

```javascript
// 같은 컬럼에서 연속된 동일 데이터를 세로 방향으로 병합
grd_gridView1.mergeCells("bycol");

// 병합 해제
grd_gridView1.mergeCells("never");
```

`mergeCells`의 주요 옵션은 다음과 같습니다.

- `never`: 병합하지 않음 또는 병합 해제
- `bycol`: 같은 컬럼에서 연속적으로 같은 데이터인 행 병합
- `byrow`: 같은 행에서 연속적으로 같은 데이터인 컬럼 병합
- `bycolrec`: `bycol` 병합 후 병합되지 않은 셀을 대상으로 `byrow` 수행
- `byrowrec`: `byrow` 병합 후 병합되지 않은 셀을 대상으로 `bycol` 수행
- `byrestriccol`: 왼쪽 컬럼의 병합 상태를 기준으로 우측 컬럼 병합
- `byrestricrow`: 위쪽 행의 병합 상태를 기준으로 아래 행 병합

`colMerge="true"`는 실제 셀 병합이 아니라 동일 값의 border를 제거해 병합처럼 보이게 하는 방식입니다. 병합된 셀 기준의 정렬이나 실제 병합 처리가 필요하면 `mergeCells` 방식을 사용해 주세요. 병합이 적용되지 않거나 조회/필터 후 풀리는 경우에는 사용 중인 엔진 버전, `gridView` XML, 데이터 예시, 재현 절차를 함께 확인해야 합니다.

`submission` 요청의 timeout은 `Submission` 객체의 `timeout` 속성에 설정합니다. 해당 시간 안에 응답이 오지 않으면 error callback, 즉 오류 처리 흐름이 실행됩니다.

적용 방법은 다음과 같습니다.

1. 화면 XML에서 대상 `submission` 객체를 확인합니다.
2. 해당 `submission`에 `timeout` 속성을 지정합니다.
3. 값은 timeout 시간으로 설정하며, 유사 가이드 기준 단위는 ms입니다.
4. 비동기 통신 기준으로 적용 여부를 확인해 주세요.

예시는 다음과 같습니다.

```xml
<xf:submission
    id="sbm_search"
    action="/sample/search"
    method="post"
    mediatype="application/json"
    mode="asynchronous"
    timeout="60000">
</xf:submission>
```

위 예시는 `sbm_search`라는 사용자 정의 submission ID에 60초 timeout을 설정한 예입니다. `timeout` 시간이 초과되면 submission 오류 처리 이벤트 또는 공통 error handler에서 후속 처리를 구성할 수 있습니다.

selectBox 항목은 `setNodeSet`으로 `dataList`를 동적으로 바인딩할 수 있습니다. 그리드 컬럼의 `inputType`이 `select`, `autoComplete`, `checkcombobox`인 경우에는 `gridView.setColumnNodeSet`으로 컬럼 단위 itemset을 변경할 수 있습니다.

적용 방법은 다음과 같습니다.

1. selectBox에 표시할 항목용 `dataList`를 준비합니다.
2. 조회 또는 조건 변경 후 `dataList` 데이터를 갱신합니다.
3. 일반 selectBox는 `setNodeSet(nodeset, label, value)`를 호출합니다.
4. 그리드 컬럼 select는 `setColumnNodeSet(colIndex, nodeset, label, value)`를 호출합니다.

아래 예시의 `selectbox1`, `dlt_codeList`, `grd_list`, `lbl`, `code`, `itemName`은 사용자 정의 예시이며 공식 API명이 아닙니다. 공식 API명은 `setNodeSet`, `setColumnNodeSet`, `setCellData`입니다.

```javascript
// 일반 selectBox에 dataList를 동적으로 바인딩
// nodeset: "data:" + dataList ID
// label: label로 사용할 dataList 컬럼 ID
// value: value로 사용할 dataList 컬럼 ID
selectbox1.setNodeSet("data:dlt_codeList", "lbl", "code");

// dataList 값을 스크립트로 변경
dlt_codeList.setCellData(0, "lbl", "사과");
dlt_codeList.setCellData(0, "code", "APPLE");

// gridView의 select 컬럼 itemset을 컬럼 단위로 변경
grd_list.setColumnNodeSet("itemName", "data:dlt_codeList", "lbl", "code");
```

조건에 따라 항목을 필터링해야 하는 경우에는 조건에 맞는 데이터만 `dataList`에 구성한 뒤 다시 `setNodeSet` 또는 `setColumnNodeSet`을 호출하는 방식으로 적용해 주세요. 유사 사례 기준으로 그리드의 특정 컬럼 select를 행마다 서로 다른 `dataList`로 직접 바인딩하는 API는 제공되지 않으므로, 행별로 완전히 다른 목록이 필요하면 개별 `selectBox` 컴포넌트를 배치하는 화면 구조도 검토가 필요합니다.

`dynamicCreate`는 런타임에 WebSquare 컴포넌트를 동적으로 생성할 때 사용하는 API입니다. 기본 형식은 `$p.dynamicCreate(id, componentName, options, parent)`이며, 생성할 컴포넌트 ID, 컴포넌트명, 생성 옵션, 부모 컴포넌트 객체를 순서대로 지정합니다.

적용 절차는 다음과 같습니다.

1. 동적으로 생성할 컴포넌트를 추가할 부모 컴포넌트를 먼저 준비합니다.
2. `$p.dynamicCreate`의 `id`에는 화면 내에서 중복되지 않는 컴포넌트 ID를 지정합니다.

1. 자식 WFrame에서 부모 화면으로 값을 전달하거나 부모 함수를 호출할 경우 `$p.parent()`로 부모 Scope에 접근합니다.
2. 부모 화면에서 WFrame 내부 함수나 컴포넌트를 호출할 경우 `wframeID.getWindow()`로 자식 WFrame의 Scope 객체를 얻은 뒤 접근합니다.
3. WFrame을 `setSrc()`로 로딩하면서 데이터를 전달할 경우 `dataObject`는 JSON 타입으로 전달하고, `dataObject.data`에는 필요한 값을 설정해 전달합니다.

```javascript

// scwin.fn_setParentData는 부모 화면에 직접 선언한 사용자 정의 예시이며 공식 API명이 아닙니다.

```

```javascript
};
```
