`gridView`에서 기본 셀 병합은 `mergeCells` 속성 또는 `mergeCells()` API로 적용할 수 있습니다. 동일한 데이터가 연속된 셀을 기준으로 병합하며, 특정 컬럼만 병합하려면 `mergeCol`을 함께 지정합니다.

적용 방법은 다음과 같습니다.

1. 컬럼 방향으로 같은 값이 연속된 행을 병합하려면 `mergeCells="bycol"`을 사용합니다.
2. 특정 컬럼만 병합하려면 `mergeCol="컬럼ID"`를 지정합니다.
3. 여러 컬럼을 지정할 경우 콤마(`,`)로 구분합니다.
4. 좌측 컬럼의 병합 상태를 기준으로 우측 컬럼을 병합하려면 `mergeCells="byrestriccol"` 방식을 검토합니다.

예시는 다음과 같습니다.

```xml
<w2:gridView id="grd_gridView1"
    dataList="dataList1"
    mergeCells="bycol"
    mergeCol="col1,col3">
</w2:gridView>
```

화면 로딩 후 스크립트에서 적용하는 경우에는 다음과 같이 호출할 수 있습니다.

```javascript
scwin.onpageload = function() {
    grd_gridView1.mergeCells("bycol");
};
```

주요 옵션은 다음과 같습니다.

- `bycol`: 같은 컬럼에서 연속적으로 같은 데이터가 있는 행을 병합합니다.
- `byrow`: 같은 행에서 연속적으로 같은 데이터가 있는 컬럼을 병합합니다.
- `bycolrec`, `byrowrec`: 한 방향 병합 후 남은 셀을 다른 방향으로 추가 병합합니다.
- `byrestriccol`: 왼쪽 컬럼의 병합 상태를 기준으로 현재 컬럼을 병합합니다.
- `byrestricrow`: 위쪽 행의 병합 상태를 기준으로 현재 행을 병합합니다.
- `never`: 병합하지 않습니다.

`colMerge`는 실제 셀 병합이 아니라 동일 데이터의 border를 제거해 병합처럼 표현하는 방식이므로, 병합 셀 기준 정렬이나 실제 병합 제어가 필요하면 `mergeCells` 계열을 사용해 주세요. 병합 결과가 의도와 다르면 사용 중인 WebSquare 엔진 버전, `gridView` XML, `dataList` 샘플 데이터를 함께 전달해 주시면 확인이 가능합니다.

`submission` 요청의 timeout은 `Submission`의 `timeout` 속성으로 설정할 수 있습니다. 값의 단위는 ms이며, 설정 시간을 초과하면 `submiterror` 또는 `errorHandler`로 오류 처리를 받을 수 있습니다.

적용 방법은 다음과 같습니다.

1. 화면 XML의 `xf:submission`에 `timeout` 속성을 지정합니다.
2. `mode="asynchronous"`인 submission에서 timeout 적용 여부를 우선 확인합니다.
3. timeout 발생 시 후속 처리가 필요하면 `ev:submiterror` 또는 `errorHandler`에 오류 처리 함수를 연결합니다.
4. 공통 기본값을 관리하는 환경이라면 설정 파일의 `/WebSquare/submission/timeout/@value` 설정 여부도 함께 확인합니다.

예시는 다음과 같습니다.

```xml
<xf:submission
    id="sbm_search"
    ref="data:json,dlt_request"
    target="data:json,dlt_result"
    action="/sample/search"
    method="post"
    mediatype="application/json"
    encoding="UTF-8"
    mode="asynchronous"
    timeout="60000"
    ev:submiterror="scwin.sbm_search_submiterror">
</xf:submission>
```

```javascript
scwin.sbm_search_submiterror = function(e) {
    // 사용자 정의 오류 처리 함수 예시입니다.
    // timeout 초과 또는 통신 오류 발생 시 사용자 안내 처리 등을 구현합니다.
    alert("요청 처리 시간이 초과되었습니다. 잠시 후 다시 시도해 주세요.");
};
```

별도 설정이 없는 경우 유사 사례 기준으로 submission timeout 기본값은 `0`으로 안내된 사례가 있으며, 이는 무한 대기 의미로 사용됩니다. 다만 실제 대기 동작은 브라우저, 네트워크, WAS, 프록시, 방화벽 등의 timeout 설정 영향을 받을 수 있습니다.

사용 중인 WebSquare 엔진 버전에 따라 지원 방식이나 적용 범위가 다를 수 있으므로, 정확한 확인을 위해 엔진 빌드 버전과 해당 `submission` XML 선언부를 함께 전달해 주시면 추가로 확인하겠습니다.

selectBox 항목을 `dataList` 기준으로 동적으로 바인딩하려면 `gridView.setColumnNodeSet()`을 사용할 수 있습니다. 이 API는 그리드 컬럼 단위로 itemset의 `nodeset`, `label`, `value`를 변경하는 기능이며, `select`, `autoComplete`, `checkcombobox` inputType에서 지원됩니다.

적용 방법은 다음과 같습니다.

1. 선택 항목으로 사용할 `dataList`를 준비합니다.
2. 그리드 컬럼의 `inputType`을 `select`로 설정합니다.
3. 조회 완료 또는 조건 변경 시점에 `gridView.setColumnNodeSet(colIndex, nodeset, label, value)`를 호출합니다.
4. `nodeset`에는 `"data:" + dataListId` 형식으로 지정합니다.
5. `label`, `value`에는 해당 `dataList`의 컬럼 ID를 지정합니다.

예시는 다음과 같습니다.

```javascript
// gridView1, codeList, itemName은 사용자 정의 예시 ID이며 공식 API명이 아닙니다.
// name, code는 codeList dataList에 존재하는 컬럼 ID 예시입니다.

gridView1.setColumnNodeSet("itemName", "data:codeList", "name", "code");
```

조건에 따라 selectBox 항목을 다르게 보여야 하는 경우에는 조건에 맞는 데이터를 `dataList`에 구성한 뒤, 해당 `dataList`를 `setColumnNodeSet()`으로 컬럼에 다시 연결하는 방식으로 처리해 주세요. 다만 그리드 동일 컬럼에서 row별로 서로 다른 `dataList`를 각각 직접 바인딩하는 API는 참고 사례 기준으로 제공되지 않으므로, row별 항목 구성이 필수인 경우에는 개별 selectBox 컴포넌트를 사용하는 화면 구조도 검토가 필요합니다.

주의사항은 다음과 같습니다.

- `setColumnNodeSet()`은 컬럼 단위 적용 API입니다.
- `nodeset` 값은 `"data:codeList"`와 같이 `data:` prefix를 포함해야 합니다.
- 실제 적용 전 사용 중인 WebSquare 엔진 버전과 그리드 컬럼의 `inputType` 설정을 확인해 주세요.

`dynamicCreate`를 사용하면 런타임에 WebSquare 컴포넌트를 동적으로 생성할 수 있습니다. 기본 형식은 `$p.dynamicCreate(id, tagName, options, parent, itemSet)`이며, 생성할 컴포넌트 ID, 컴포넌트 태그명, 속성 객체, 부모 컴포넌트를 지정하는 방식으로 사용합니다.

적용 절차는 다음과 같습니다.

1. 동적으로 생성할 컴포넌트의 `id`를 정합니다.
2. 생성할 컴포넌트의 `tagName`을 지정합니다. 예: `"input"`, `"textbox"`, `"gridView"` 등
3. 컴포넌트 속성은 문자열 XML이 아니라 객체 형태의 `options`로 전달합니다.
4. 생성 위치가 될 부모 컴포넌트 객체를 지정합니다.
5. 생성 후에는 해당 컴포넌트를 바로 제어하기보다, 실제 렌더링 및 초기화 시점을 고려해 후속 로직을 분리합니다.

예시는 다음과 같습니다.

```javascript
// grp_dynamicArea는 화면에 미리 정의된 group 컴포넌트라고 가정합니다.
// "dyn_textbox1"은 사용자 정의 ID 예시입니다.
$p.dynamicCreate(
    "dyn_textbox1",
    "textbox",
    {
        label: "동적 텍스트",
        style: "width:150px;height:24px;"
```

적용 방법은 다음과 같습니다.

1. 부모 화면에 데이터를 받을 사용자 정의 함수를 `scwin`에 작성합니다.
2. WFrame 내부 화면에서 `$p.parent().scwin.함수명(data)` 형태로 호출합니다.
3. 부모 컴포넌트를 직접 제어해야 하는 경우에는 `$p.parent().컴포넌트ID.setValue(...)`처럼 부모 Scope의 컴포넌트 API를 호출합니다.

예시는 다음과 같습니다.

```javascript
// 부모 화면
scwin.receiveFromWFrame = function(data) {
    ibx_exam1.setValue(data.name);
};
```

```javascript
// WFrame 내부 화면
var data = {
    name: "홍길동"
};

// receiveFromWFrame은 사용자 정의 함수명입니다.
$p.parent().scwin.receiveFromWFrame(data);
```

부모 화면의 컴포넌트를 직접 제어하는 경우는 다음과 같이 사용할 수 있습니다.

```javascript
// WFrame 내부 화면
$p.parent().ibx_exam1.setValue("전달할 값");
```

단, WFrame의 `scope` 설정이 적용되지 않은 구조에서는 `$p.parent()`가 부모 WFrame Scope가 아니라 최상위 페이지 Scope를 반환할 수 있으므로, 현재 WFrame의 `scope` 설정과 화면 포함 구조를 함께 확인해 주시기 바랍니다. 여러 WFrame이 중첩된 구조라면 직접 컴포넌트를 참조하는 방식보다 부모 화면에 전달용 `scwin` 사용자 정의 함수를 두고 그 함수를 호출하는 방식이 유지보수에 유리합니다.

2. 행 전체를 변경할 경우 `gridView_id.setRowBackgroundColor(rowIndex, color)`를 호출합니다.
3. 특정 셀만 변경할 경우 `gridView_id.setCellBackgroundColor(rowIndex, columnInfo, color)`를 호출합니다.
